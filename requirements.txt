# STAMP -- what the pipeline imports, and nothing else.
#
# Requires Python 3.10+.  gymnasium>=1.2.0 ships no wheel for 3.9 or below (pip
# resolves it to 1.1.1 there, silently) and numpy>=2.0 refuses to install below
# 3.9 at all.  On a cloud box whose system `python3` is still 3.8 (Ubuntu 20.04
# TPU/GPU images, most commonly) `pip install -r requirements.txt` fails with
# "No matching distribution found for gymnasium<2,>=1.2.0" -- that error means
# the interpreter, not this file, needs upgrading.  Check first:
#
#   python3 --version
#
# If it is below 3.10, get a newer interpreter rather than loosening the pins
# below -- this checkout of MATE was verified against numpy 2.x, and quietly
# falling back to numpy 1.x changes what is actually being run:
#
#   conda create -n stamp python=3.11 && conda activate stamp
#   # or, without conda: pyenv install 3.11.9 && pyenv local 3.11.9
#
# Verified combination (Python 3.13, CPU):
#   gymnasium 1.2.3 | numpy 2.4.6 | scipy 1.17.1 | torch 2.12.0 | PyYAML 6.0.3
#
# The simulator is NOT installed from here.  `MATE-main` is a source checkout
# next to this file; `src/envs/config_resolver.py` puts it on the path, and
# `MATE_ROOT` overrides where it looks.  Do not `pip install -e MATE-main`:
# its pyproject pulls jupyter, matplotlib, pandas, stable-baselines3, OpenCV,
# pygame and swig, none of which this pipeline touches -- measured by importing
# `mate` and stepping the wrapper with all nine blocked.

# --- the environment ---------------------------------------------------------
# MATE-main is a gymnasium port.  The old `gym` (0.26) package cannot run it;
# if both are installed, neither is used by accident -- nothing here imports gym.
gymnasium>=1.2.0,<2
# 2.x is required: this checkout of MATE is not numpy-1.x compatible.
numpy>=2.0,<3
# mate.utils imports scipy.interpolate at module load.
scipy>=1.11
# Scenario files under mate/assets are YAML.
PyYAML>=6.0.2

# --- the learned part --------------------------------------------------------
# The flow-matching head and the MPPI planner are both plain torch; no CUDA is
# required, and on this problem size a GPU is a modest speedup because the
# simulator itself is single-threaded numpy.  For a CUDA build, install torch
# from the PyTorch index instead of this line:
#     pip install --index-url https://download.pytorch.org/whl/cu124 torch
torch>=2.8

# --- optional ----------------------------------------------------------------
# Dashboard logging, enabled with `--wandb`.  `metrics.jsonl` is written either
# way, so a cluster with no outbound network loses nothing by omitting this.
# wandb>=0.17
#

# never import these:
# pygame>=2.6.1
